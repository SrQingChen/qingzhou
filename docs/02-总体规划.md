# 青舟 总体规划

> 版本：v1.0（2026-09-22） · 作者：SrQingChen
> 定位：局域网/热点场景下，安全前提下**发现最快、传输最快**的安卓互传工具，澎湃 OS 1/2/3 跨版本深度适配。

> **实施状态（2026-09-22）**：M0~M4 已完成并通过编译与加密层单测（8/8），
> 工程落地相对本规划有两处优化：四个 feature 模块合并为单 `:feature:home`（分区共享状态更自然）；
> 未引入 DataStore/kotlinx-serialization，持久化沿用「手写 JSON + 防抖落盘」零依赖模式。
> 待真机验收项：双机发现时延、5GHz 热点吞吐（目标 ≥40MB/s）、OS1+OS3 超级岛降级链。

## 1. 产品定义

| 项 | 值 |
|---|---|
| 应用名 | 青舟（QingZhou） |
| 包名 | io.github.srqingchen.qingzhou |
| 作者 | SrQingChen |
| 平台 | Android 8.0+（minSdk 26），重点适配 HyperOS 1/2/3，兼容其他 Android ROM |
| 核心承诺 | ① 发现快（<1s 可见、热点场景零等待直连）② 小消息毫秒级直达（免握手单包加密）③ 大文件榨干链路（分块多流，目标 40~90MB/s）④ 全程加密、默认不自动接收 |
| 差异化 | 分级安全策略（小消息轻通道 / 文件重通道）、超级岛四级降级+双轨制、Shizuku 可选增强、玻璃质感立体 UI |

### 核心场景

1. **同一 WiFi**：两台手机连同一路由器 → 自动发现 → 互发文本/文件/剪贴板。
2. **一方开热点**：另一台连上热点 → 零等待发现（网关直连探测）→ 高速直传（单跳空口，最快场景）。
3. **无任何网络**：App 内一键 `startLocalOnlyHotspot()` 自建局域网 /（v1 后期）WiFi Direct 直连。
4. **传输全程**：超级岛/灵动通知实时显示进度与速率，息屏不断流。

### 2.2 技术栈（与尘露对齐，已验证可跑通中文路径 + AGP 9 工具链）

- Kotlin 2.4.20（K2）/ AGP 9.4.1 / Gradle 9.7.1 / JDK 21

- 纯 Jetpack Compose（BOM 2026.09.00，Material3），单 Activity、无 Navigation 库（底部 NavigationBar + 分区索引）、无 DI 框架（object 单例 + Application 组装根）

### 2.3 技术选型结论（依据见 01-调研报告）

| 层 | 选型 |
|---|---|
| 发现主通道 | UDP 广播/多播 announce（端口 39527/UDP，持 MulticastLock 周期重取） |
| 热点加速 | 客户端读网关 IP → TCP 直连探测（端口 39528/TCP），零等待 |
| BLE 辅助 | 广播设备指纹摘要 + GATT 交换链路信息（发现页开关，省电偏好默认关） |
| 数据链路优先级 | 同 WiFi 基础设施 > 热点直连 > LocalOnlyHotspot > WiFi Direct（10s 超时回退） |
| 传输 | 控制通道单 TCP + 数据通道 N 条并行 TCP（默认 4，可配 1~8），SO_BUF 8MB，分块 4MB |
| 零拷贝 | 明文块经 FileChannel/mmap 读取 → 逐块 AES-256-GCM（ARMv8 硬件）→ 发送 |
| 安全 | Noise XX（配对）/ IK（复用）+ ChaCha20-Poly1305（小消息/握手）+ BLAKE2b（校验）+ 指纹 TOFU |
| 排除项 | BBR、KCP、QUIC（后期实验）、WiFi Aware（仅探测报告）、蓝牙数据聚合 |

## 3. 协议设计：「舟协议 Boat Protocol v1」

### 3.1 身份与配对

- 每设备生成静态 X25519 密钥对，私钥存 Android Keystore 加密文件。
- **指纹** = SHA-256(静态公钥) → 展示为 6 位数字短码 + 8 色块图形（快速人工核对）。
- **首次配对**（Noise XX，1~2 RTT）：
  1. 发起方发送握手包（含临时公钥）；
  2. 双方弹出确认卡：显示对端设备名 + 指纹短码/色块，人工核对一致后确认；
  3. 完成双向认证 + 前向保密，双方保存对端静态公钥（已配对设备库）。
- **复用会话**（Noise IK，1 RTT，毫秒级）：已配对设备直接派生会话密钥，无人工介入。
- 防重放：每包 64-bit 计数器 + 接收滑动窗口。

### 3.2 分级安全策略（核心差异化）

| 级别 | 内容 | 通道 | 开销 |
|---|---|---|---|
| **微消息** | ≤64KB 文本/剪贴板/链接，已配对设备 | UDP + ChaCha20-Poly1305 单包 AEAD，免握手直发 | 毫秒级送达，无建连成本 |
| **会话协商** | 元数据/块调度/心跳 | 控制 TCP（Noise IK 加密帧） | 单连接 |
| **文件流** | 任意大小文件/文件夹 | 数据 TCP N 条并行，4MB 分块逐块 AES-256-GCM + 块序号，全文件 BLAKE2b | 硬件加速，吞吐无损 |

安全红线：**绝不零点击自动接受**——接收请求默认弹确认（设备名+指纹+大小）；设置里可对**已配对**设备开启"自动接收"。来自未配对设备的请求必须显式配对确认。

### 3.3 发现协议

- **announce 包**（UDP 39527，广播 + 多播 224.0.0.167 双发）：设备名/型号/OS 版本/指纹摘要/协议版本/能力位（ax 链路/P2P/BLE/方向）+ 本次会话端口。
- 节奏：入网立即 announce ×3（100ms 间隔）→ 周期心跳（省电 5s / 均衡 2s / 敏捷 800ms）。
- 对 announce 的响应：单播 register 回包（含自己的完整信息）→ 双向可见。
- **热点零等待**：检测到网关 IP（LinkProperties.getRoutes）→ 立即向 网关:39528 发 TCP probe（携带自描述帧）→ 免广播等待。
- **NSD 旁路**：注册 `_qingzhou._tcp`（生态兼容，非关键路径）。
- **BLE 旁路**（可选开）：ADV 广播 16 字节指纹摘要；GATT 连接后仅交换「开热点/连热点」引导信息，不做数据面。

### 3.4 传输协议

- **会话建立**：控制通道协商（协议版本、块大小、并行度、断点 token、文件清单+BLAKE2b）。
- **块调度器**（多链路感知设计，为 v2 聚合预留）：
  - `chunk → link → stream` 三级映射；v1 单链路（WiFi infra/热点），N 条流；
  - 最闲流优先分配；接收端按块序号乱序重组，直接 FileChannel 预分配写盘；
  - 单块 AEAD 校验失败只重传该块；断点续传 = 块位图 + 会话 token。
- **小文件批量**：清单合并 + 流水线 + 背压队列（吸取 LocalSend 4000 文件卡顿教训，UI 全异步）。
- **收尾**：全文件 BLAKE2b 校验 → 完成帧 → 超级岛收岛 → 媒体库扫描广播。
- **受限网络处理**：热点无网时所有 Socket `bindSocket` 到 TRANSPORT_WIFI 的 Network。

### 3.5 运行时优化

- 传输全程 `WifiLock WIFI_MODE_FULL_HIGH_PERF`；小消息期 `WIFI_MODE_FULL_LOW_LATENCY`（API 29+，低版本降级 FULL_HIGH_PERF）。
- MulticastLock 传输+发现期持有，周期重取（防失锁）。
- 息屏不断流：dataSync 前台服务；onTimeout（OS2+ 6h 上限）自愈重启。

## 4. 超级岛与通知中心（四级降级）

```
检测链：notification_focus_protocol >= 3 且 island 特性？
 ├─ ① OS3 超级岛：param_island（smallIslandArea.combinePicInfo.progressInfo 环形进度
 │    + bigIslandArea 文件名/速率/timerInfo 剩余时间 + 完成时 cancel:true）
```

- 接收确认、传输完成、微消息到达三类事件也走通知中心（岛上可放「接受/拒绝」actionInfo 按钮）。

## 6. UI/UX 设计（玻璃质感立体）

### 6.1 布局：单 Activity + 底部四大分区

```
┌────────────────────────────┐
│                            │
│      当前分区内容区          │
│   （玻璃卡片层叠+柔光斑）     │
│                            │
├────────────────────────────┤
│  🧭发现   📦传输   📥收件箱  ⚙️设置  │
└────────────────────────────┘
```

- **发现**（首页）：本机状态卡（在线状态/链路质量/IP/接收开关）+ 设备列表（头像=指纹色块、型号、链路标识 WiFi6/热点/P2P、信号）+ 底部快捷条（发送文本/粘贴板/文件入口）+ 下拉刷新触发敏捷发现。设备点击 → 底部玻璃抽屉（设备详情 + 发送文本/文件/自动接收开关/取消配对）。
- **传输**：进行中任务卡（玻璃进度环 + 实时速率 + 剩余时间 + 分块网格图）+ 排队/历史（成功/失败/取消，可重发）。
- **收件箱**：接收的文本/链接/剪贴板（一键复制/二维码）、文件（按类型分组，跳转系统打开）。
- **设置**：传输偏好（省电/均衡/极速三档 + 并行流数/块大小高级项）、发现偏好（间隔/BLE 开关/NSD）、安全（已配对设备管理/自动接收白名单/加密说明）、超级岛（兼容模式开关+Shizuku 状态）、Shizuku 管理页、存储（下载目录 SAF）、网络诊断、关于（作者 SrQingChen、开源协议、版本）。

### 6.2 视觉语言

- **主题**：玻璃拟态立体——多层半透明表面 + 1px 高光描边 + 柔光斑背景（复用尘露 ChenLuBackground 思路）+ 关键面 RenderEffect blur（API 31+，低版本自动降级为纯层叠）；深浅色 + Material You 动态色。
- **品牌色**：青碧色系（主色 #00838F 系，「青舟」意象：青色水波 + 舟行轻快），暗色模式提亮为 #4DD0E1。
- **动效**：设备出现波纹扩散、传输进度环流体旋转、完成时玻璃卡片光泽扫过、超级岛 2Hz 能量流动环（尘露经验）。
- 性能：动效全部数据驱动/Compose 动画，悬浮场景不用 blur，列表用 LazyColumn + key。

### 6.3 首次引导页（三屏）

1. 权限申请（通知/附近设备/蓝牙，含"为什么需要"说明）；
2. 澎湃 OS 保活引导（省电无限制/关 WLAN 助理/锁后台，按 ROM 版本动态展示入口深链）；
3. Shizuku 可选引导（说明增强功能，可跳过）。

## 7. 工程里程碑

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| **M0 骨架** | build-logic + 全模块空壳 + 主题/玻璃组件 + MainActivity 四分区框架 + 文档 | 工程可装可跑，分区切换流畅 |

每里程碑完成后真机验证（小米 OS1 + OS3 双机为主，辅一台非小米设备）。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 超级岛白名单拦截 | 双轨制（标准字段+降级 / Shizuku 兼容模式）；后续可走官方申请 |
| Powerkeeper 锁屏杀后台/断网 | dataSync FGS + WifiLock + 引导页深链 + 接收开关打开时提示 |
| MulticastLock 失锁 | 周期重取 + 网关直连探测兜底 + TCP probe |
| 热点被判"受限网络"路由到蜂窝 | ConnectivityManager bindSocket 到 WIFI transport |
| WLAN 助理断开"无法上网"的热点 | 引导页提示关闭（按 ROM 检测） |
| dataSync FGS 6h 上限（OS2+） | onTimeout 自愈重启 + 大任务分会话 |
| WiFi Direct GO 协商失败/慢 | 10s 超时 → 自动回退提示开热点 |
| 非 ASCII 项目路径 | 继承尘露配置（overridePathCheck、手写 Binder、PREFER_SETTINGS） |

## 10. v2+ 展望（不承诺）

- 超级岛官方权限申请落地（替换兼容模式依赖）
- 桌面端（Windows/Mac）伴侣客户端
